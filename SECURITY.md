# Security Policy

## Report a vulnerability privately

Do not open a public issue for a suspected vulnerability. Use GitHub's **Report a vulnerability** option on this repository's Security page. Include the affected version, impact, reproduction steps, and the minimum evidence needed to investigate. Remove passwords, license keys, private keys, tokens, personal files, and unrelated user data.

Nomex will acknowledge a usable report when operationally possible, investigate it, and coordinate remediation and disclosure based on severity. This is not a promise of a specific response or fix time and does not create a bug-bounty entitlement.

## Safe-harbor boundaries

Testing requires prior written authorization unless performed only on systems and accounts you own. Do not access other users' data, degrade service, use social engineering, persist after demonstrating impact, or publish exploitable details before Nomex has had a reasonable opportunity to investigate. The EULA and Acceptable Use Policy continue to apply except where applicable law provides otherwise.

## Supported versions

Security fixes are normally delivered for the latest Stable release. Older releases may be unsupported. Check the [latest GitHub release](../../releases/latest) and the in-app update page.

## Download safety

Official release assets use the exact installer name `NomexShift-Setup.exe` and include `SHA256SUMS.txt`. Verify the checksum and Authenticode signature when present. A checksum alone does not prove publisher identity.
